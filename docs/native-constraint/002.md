# ObjTypeAnalyzer

FsNative does not support the `obj` type, `box`, or `unbox` operations. All types must be statically known at compile time.

## Problem

```fsharp
// These will trigger the analyzer
let x: obj = box 42           // FSNATIVE-002 (box) and FSNATIVE-004 (obj type)
let y: int = unbox x          // FSNATIVE-003 (unbox)
let f (x: obj) = x            // FSNATIVE-004 (obj parameter)
```

## Fix

Use generics or explicit types instead:

```fsharp
// Use generics for polymorphic code
let identity<'T> (x: 'T) = x

// Use discriminated unions for heterogeneous collections
type Value = 
    | IntVal of int 
    | StringVal of string
    | FloatVal of float

let values = [IntVal 42; StringVal "hello"; FloatVal 3.14]
```

## Why This Matters for Native Compilation

`obj` and boxing operations require:

- Runtime type information (RTTI)
- Dynamic dispatch
- Heap allocation for boxed values

In FsNative:

- All types are resolved at compile time
- No runtime type checks needed
- Values can be stack-allocated when sizes are known

## Error Codes

- `FSNATIVE-002`: `box` operation detected
- `FSNATIVE-003`: `unbox` operation detected  
- `FSNATIVE-004`: `obj` type usage detected
